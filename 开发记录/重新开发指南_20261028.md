## 3. 如何理解工程结构

可以把 App 想成一家小仓库：

- `Item` 是每件东西的登记卡，记录图片、名称、数量以及放在哪里。
- `Container` 是柜子、背包等收纳位置。房间中的家具图片，是这个收纳位置的可视化外观。
- `ContentView` 是仓库大厅，负责家的预览、容器切换、物品列表和批量操作。
- `HomeDecorationView` 是布置房间的画布。
- `AddItemView` 是登记窗口，负责录入和保存，并启动 AI 识别。
- `DoubaoService` 负责联网识别；`ImageUtils` 负责图片加工。
- `woyoushaApp` 是启动入口，负责建立数据库和旧图片迁移。

当前没有独立服务器工程，物品记录主要存在安装 App 的设备里。豆包接口是外部服务。

目前界面直接通过 `@Query` 读取数据、通过 `modelContext` 修改数据；已经拆出图片工具、AI 服务和拖拽组件，但首页和装修页仍较集中，分别约 1,019 行和 826 行。后续可以按功能拆分，并把跨页面共用的数据操作集中管理。

## 4. 继续开发前应优先处理的实际问题

### 4.1 数据保存与旧版本兼容

启动代码在 DEBUG 模式遇到数据库加载失败时，会尝试删除旧数据库后重建，见 `woyoushaApp.swift:16-49`。这是早期开发兜底逻辑。继续修改模型前，应先备份有价值的测试数据，再设计正式的数据库升级方案。

部分保存操作使用 `try? modelContext.save()`，失败后没有明确反馈。后续应统一数据操作和错误处理，让“界面显示成功”和“数据确实保存成功”保持一致。

### 4.2 AI 流程已有基础，但尚需统一状态

当前实际流程是：选照片 → 本地抠图和描边 → 允许保存 → 如果名称为空或为“新物品”，保存时启动豆包识别 → 返回列表显示识别状态。

需要优先回归以下情况：

- 抠图完成时，页面已显示“识别中”，实际联网请求在保存时才启动。
- 用户手动填写名称后，新物品仍可能被设置为 `pending`，但不会启动识别请求，随后可能被超时检查标为失败。
- 当前失败样式会把原名称显示为橙色，尚未完整实现 PRD 中“识别失败”的提示和重试流程。
- “后台识别”目前表示离开录入页面后任务仍可继续；没有实现 App 被系统终止后仍继续处理、自动恢复的任务机制。
- 60 秒超时是进入首页或详情页时检查，尚不是持续运行的计时器。

对应代码：`AddItemView.swift:274-446`、`Item.swift:128-140`、`ContentView.swift:856-874`。

### 4.3 发布前的 AI 配置

豆包密钥目前随 `Info.plist` 打包进 App，源码注释中的“没有硬编码”不代表密钥受到保护。对外发布前应改为服务端代调用，避免在客户端分发长期密钥。

本次没有发送图片或调用豆包接口，因此尚未验证当前密钥、模型权限和服务是否仍有效。

## 6. TRAE 与 Xcode 如何配合

TRAE 负责理解需求、读写代码和运行开发命令。Xcode 负责苹果平台的编译、运行、真机签名和调试。

两者打开同一份工程，就能共同使用磁盘上的源码；无需来回复制 Swift 文件。建议主要在 TRAE 修改代码，在 Xcode 查看界面、设置断点和体验 App。[cite:1]

TRAE 读取错误有两条途径：

| 途径 | 可以得到什么 | 使用条件 |
| --- | --- | --- |
| TRAE 调用 `xcodebuild` | 本次命令编译产生的错误、警告、日志、结果包 | 本机有 Xcode，智能体可使用终端 |
| TRAE 连接 Xcode MCP | 读取和调用 Xcode 实际公开的项目、问题、构建等工具 | Xcode 允许访问，TRAE 已配置并加载 MCP，工具列表有效 |

命令行编译已经在本次核查中实际使用；MCP 的完整连接尚未通过验证。编译日志也不会自动包含真机运行时的所有崩溃信息。

## 7. 项目级 Xcode MCP 配置

本次已新增项目文件 `.trae/mcp.json`：

```json
{
  "mcpServers": {
    "xcode": {
      "command": "/usr/bin/xcrun",
      "args": ["mcpbridge"]
    }
  }
}
```

`command` 是启动程序；`args` 表示让它启动 Apple 提供的 Xcode 连接桥。它不含账号、密钥或固定进程编号。Apple 官方使用 `xcrun mcpbridge` 将外部智能体接入 Xcode；TRAE 官方支持项目级 `.trae/mcp.json` 和这种 stdio 配置。[cite:1][cite:2]

完成连接的操作：

1. 在 Xcode 打开 `woyousha/woyousha.xcodeproj`，保持 Xcode 和工程窗口开启。
2. 在 Xcode → Settings → Intelligence，确认 **Allow External Agents to Use Xcode Tools** 允许外部访问。截图中已显示 `Always`。
3. 在 TRAE → 设置 → MCP，启用“项目级 MCP”功能，让 TRAE 加载已有的 `.trae/mcp.json`。[cite:2]
4. 确认列表出现 `xcode`，启用或重新连接。若客户端尚未加载新配置，可重新打开工作区或新建对话。
5. 确认当前使用的智能体有权调用这个 MCP；自定义智能体可在“工具 / MCP”中勾选它。[cite:3]
6. 若 Xcode 弹出连接请求，允许来自 TRAE 的连接。
7. 在 TRAE 输入：“请读取 Xcode 当前打开的项目和问题列表，检查这个工程的编译错误。”

成功标准是能列出实际 Xcode 工具，并读取到项目或问题；只有开关为 `Always`、或者连接初始化成功，还不算完成。

本次诊断出现两种结果：默认连接曾返回“MCP 访问未启用”；明确指向正在运行的 Xcode 时，初始化成功，但工具列表为空。两者与截图所示状态存在差异，需要在客户端重新允许访问并重连后确认。`mcp-server status` 还显示无界面服务未启用，但这不等于截图里的图形界面开关状态。

如果工具列表仍为空，先确认工程窗口已打开，重新连接 MCP，再重新启动 Xcode / TRAE。多个 Xcode 实例时，可临时使用 Apple 支持的 `MCP_XCODE_PID` 指定实例；进程编号随启动变化，不应写死到项目配置。日常图形界面协作无需先启用需要管理员权限的 headless 服务。

截图下方的“ChatGPT in Xcode”“Claude”等入口，是在 Xcode 内使用另一套 AI 助手的配置。继续使用 TRAE 时，关键是外部 MCP 连接。

## 8. 截图中的 No Accounts 如何处理

这是签名账号问题：Xcode 需要用开发者身份给 App 签名，才能装到 iPhone 上。它与 TRAE 能否读取代码、MCP 是否连接是分别配置的。

1. 打开 Xcode → Settings → Apple Accounts，添加用于开发的 Apple 账号。
2. 点击工程 → TARGETS → `woyousha` → Signing & Capabilities。
3. 保持 **Automatically manage signing** 开启。
4. 在 **Team** 选择该账号实际可用的团队。当前工程设置中的团队，需要和登录账号的权限匹配。
5. 选择 `OGS17`，再运行。后续若出现证书、设备信任或其他签名错误，按新的具体错误处理。

当前编译检查关闭了签名，因此不能据此确认真机签名已经恢复。Apple 账号登录需要在 Xcode 的账号界面完成。

## 9. 没连上 MCP 时如何让 TRAE 读报错

直接在 TRAE 中输入：

> 请编译这个 iOS 工程，读取编译日志，解释报错原因；需要修复时保留现有数据。

智能体可以使用以下命令，在项目根目录执行编译：

```bash
# 生成模拟器 Debug 版本，并将完整编译输出保存到临时日志。
# 关闭签名仅用于模拟器编译检查，不能替代真机签名。
xcodebuild \
  -project woyousha/woyousha.xcodeproj \
  -scheme woyousha \
  -configuration Debug \
  -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath /tmp/woyousha-derived-data \
  CODE_SIGNING_ALLOWED=NO \
  build > /tmp/woyousha-build.log 2>&1
```

TRAE 随后读取 `/tmp/woyousha-build.log` 即可。这条命令是重新编译检查，不是自动读取 Xcode 屏幕里所有历史错误。

若再次出现本次已确认的宏辅助进程沙箱错误，可以在该次命令追加 `OTHER_SWIFT_FLAGS='$(inherited) -disable-sandbox'`，而不是根据连带报错修改数据模型。普通 Xcode 图形界面编译不需要先添加这个参数。

对于运行后才出现的问题：

- 编译或签名错误：在 Xcode 左侧问题列表或报告列表中复制完整错误，也可以导出日志给 TRAE。
- App 崩溃：提供调试控制台信息和调用堆栈，并描述最后做了什么操作。
- 界面和手势问题：提供截图或录屏、操作步骤、期望效果。
