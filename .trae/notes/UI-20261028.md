# 2026-10-28 原生界面更新

开发分支为 `1028update`。后续按用户反馈调整为下述风格。

## 视觉与交互

- 保留“可布置的小房间 + 物品贴纸”结构，采用接近 Duolingo 的亮绿色、粗圆角、清晰描边和凸起底边按钮；支持系统深色模式与减少动态效果。
- `AppTheme.swift` 集中管理颜色、尺寸和共用控件。修改风格优先从这里开始。
- 首页把房间操作和物品列表区分开，房间收起时裁剪画布；保留家具联动、批量拖拽、双指缩放、装修和图层操作。
- 按用户最新反馈，相机改为录入窗口内部的实时取景，使用 `AVCaptureVideoPreviewLayer` 嵌入原有圆角照片区。下方“拍一张 / 从相册选”是 App 自己的按钮；不使用 `UIImagePickerController`，也不打开独立的系统相机页面。
- 物品录入使用草稿，名称必填，照片选填；编辑取消不修改原物品。保存期间防止重复操作，失败保留草稿。
- 首页加号直接打开 `AddItemView` 弹窗，照片区自动开始实时取景，信息字段与保存按钮继续显示。拍摄后原位制作并显示贴纸，“重新拍”原位切回取景；权限不可用时仍可从相册选择或手动录入。已移除 `ItemCaptureFlow`。
- 物品列表取消矩形卡片底板、外框和卡片投影，保留照片本身的白色贴纸描边与轻阴影。
- 装修控制从 `FurnitureBubbleMenu` 替换为固定底部 `FurnitureInspector`。操作按钮至少 44pt；造型选择使用独立抽屉，主面板保持固定高度。家具缩放先预览，松手后保存；加减按钮支持小步调整。
- `FurniturePlacementRepository` 统一保存移动、图层、造型、镜像和缩放，更新造型时同步占地尺寸；操作失败提示并恢复数据，收起家具仍保留容器内的物品。

## 识别与图片处理

- 删除豆包请求实现及 Info.plist 中的旧密钥，当前没有联网识别请求。
- `ItemRecognitionService.swift` 保留禁用的服务协议。未来接入服务时实现协议，再明确设计识别触发方式和字段回填规则；目前录入页不调用识别服务。
- 保留 `Item.aiStatusRawValue` 和 `Item.aiRequestDate` 字段，避免改变已有 SwiftData 数据结构。首页启动时清理旧识别状态，旧物品可以立即编辑。
- 本地 Vision 抠图和白色贴纸描边继续保留，抠图失败保留原图并说明原因。
- `ItemEditorModel.swift` 使用任务取消与版本标记，防止旧图片的处理结果覆盖新图片。PNG 编码、缩放和描边移到后台。
- 图片重绘固定为 1 倍像素并统一方向，正式图限制 1024px，缩略图限制 200px。
- 最新相机/相册统一传递压缩数据，用 ImageIO 直接解码 1024px 小图并应用照片方向；相机控制器不再在主线程创建整张 UIImage。拍摄设置优先 `.speed`，适用于制作物品贴纸。
- `ItemPhotoProcessor` 用一条可取消的后台任务执行缩图、Vision 分离和描边。轮廓分析与边缘细化限制在 768px，生成软遮罩后与 1024px 主体合成，共用 `AlphaOutlineRenderer` 的 CIContext；只扫描 Vision 小标签图的各行边界，不扫描完整 RGBA 原图裁边。
- 照片描边只在最长边 256px 的透明度遮罩上扩边，再与清晰主体合成；移除大图高斯模糊和重复增强透明度的滤镜。处理尺寸、白边宽度和提示等待时间集中于 `PhotoProcessingSettings`。
- 录入先显示原图，再显示透明主体，最后显示贴纸；照片区底部依次提示读取/分离/白边阶段，不遮住主体。超过 2.5 秒提示可先填写信息，有原图后可选“先用原图”结束等待；处理期间可重新拍照或更换相册图片。
- 取消同时传递到 detached 任务和 Vision 请求，版本号继续隔离旧回调。主动取消保留原图与正确的照片状态；读图失败保留之前的图片；保存始终等待处理完成或用户选择原图。`PhotoPerformanceTrace` 按单调时钟记录拍照/相册读取、解码、准备分析图、Vision 推理、边缘细化、合成裁剪、白边与总等待，不包含照片内容。
