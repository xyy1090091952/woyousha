# 2026-10-28 原生界面更新

开发分支为 `1028update`。后续按用户反馈调整为下述风格。

## 视觉与交互

- 保留“可布置的小房间 + 物品贴纸”结构，采用接近 Duolingo 的亮绿色、粗圆角、清晰描边和凸起底边按钮；支持系统深色模式与减少动态效果。
- `AppTheme.swift` 集中管理颜色、尺寸和共用控件。修改风格优先从这里开始。
- 首页把房间操作和物品列表区分开，房间收起时裁剪画布；保留家具联动、批量拖拽、双指缩放、装修和图层操作。
- 相机直接展示完整的系统 `UIImagePickerController`，保留系统快门、重拍和“使用照片”。已移除自定义 overlay、子控制器与自行维护的快门状态。先在录入页完成权限检查，再打开相机；关闭后再处理回传照片。
- 物品录入使用草稿，名称必填，照片选填；编辑取消不修改原物品。保存期间防止重复操作，失败保留草稿。
- 首页加号改为 `ItemCaptureFlow` 全屏拍摄流程：相机 → 使用照片 → 信息表单。取消拍摄返回首页；权限不可用时提供相册和手动录入，编辑已有物品仍直接进入表单。
- 物品列表取消矩形卡片底板、外框和卡片投影，保留照片本身的白色贴纸描边与轻阴影。
- 装修控制从 `FurnitureBubbleMenu` 替换为固定底部 `FurnitureInspector`。操作按钮至少 44pt；造型选择使用独立抽屉，主面板保持固定高度。家具缩放先预览，松手后保存；加减按钮支持小步调整。
- `FurniturePlacementRepository` 统一保存移动、图层、造型、镜像和缩放，更新造型时同步占地尺寸；操作失败提示并恢复数据，收起家具仍保留容器内的物品。

## 识别与图片处理

- 删除豆包请求实现及 Info.plist 中的旧密钥，当前没有联网识别请求。
- `ItemRecognitionService.swift` 保留禁用的服务协议。未来接入服务时实现协议，再明确设计识别触发方式和字段回填规则；目前录入页不调用识别服务。
- 保留 `Item.aiStatusRawValue` 和 `Item.aiRequestDate` 字段，避免改变已有 SwiftData 数据结构。首页启动时清理旧识别状态，旧物品可以立即编辑。
- 本地 Vision 抠图和白色贴纸描边继续保留，抠图失败保留原图并说明原因。
- `ItemEditorModel.swift` 使用任务取消与版本标记，防止旧图片的处理结果覆盖新图片。PNG 编码、缩放和描边移到后台。
- 图片重绘固定为 1 倍像素并统一方向，正式图限制 1024px，缩略图限制 200px。

## 数据层与验证

- `ItemRepository.swift`、`ContainerRepository.swift` 负责保存与恢复，数据库保存成功后才关闭页面。
- `.trae/validation/check-storage.swift` 是独立的内存数据库冒烟验证，不访问正式数据。已通过：旧状态清理保留物品内容、草稿隔离、编辑不重复新增、无图手动录入、空名称拦截、删除容器保留物品、禁用识别。
- 已通过 iOS 17 目标的 Debug 编译检查。无 Swift 编译警告；Xcode 提示未使用 AppIntents 的元数据检查被跳过。
- 当前没有可用模拟器，命令行 Xcode MCP 受运行权限限制，因此没有取得原生页面截图或完成相机交互验证。
- 最新等轴版本已通过 Xcode 自身的 Run 动作签名、安装至 OGS17 并启动。终端直接签名曾报 `errSecInternalComponent`，无需改证书，通过 Xcode 执行后成功。
- 相机黑屏的真机根因尚未最终确认：调试附加曾被设备锁屏阻止。此次移除了自定义覆盖层，直接使用系统相机；启动成功不代表实际取景/成像已验证，需要真机点开确认。

## 程序生成像素场景

- `IsometricGeometry.swift` 统一 2:1 等轴投影、明暗规则和深度遮挡；`IsometricFurniture.swift` / `IsometricRoom.swift` 分别描述家具与房间。`PixelArtRenderer.swift` 输出原生 CGImage，不使用 WebView 或 Three.js。
- 每个物体以长、宽、高建模，再投影到 2D 像素。柜门、书脊、窗户、木纹等细节也在模型面上定义；已移除上一版家具正面水平矩形造成的角度不一致。
- 23 个家具入口及其镜像版本、2 种房间配色均已生成检查。镜像交换模型坐标轴并重新计算受光，不再直接翻转整张位图。
- `PixelArtView.swift` 缓存程序绘制的小图，放大时用 `.interpolation(.none)` 保持像素边缘。首页、家具抽屉、造型选择器统一复用，不读取旧家具/房间图片资源。
- 保留旧 `furnitureImageName` / `currentRoomImage` 编号及 SwiftData 模型结构，旧容器无需迁移。原图片资源留在工程里，但场景渲染不再调用。
- 世界坐标继续为 800×800，已有摆放记录保留。房间和家具共用单位比例；家具渲染边界自动测量，避免把不同比例的图硬拉成同样尺寸。
- 最新 `DesignPreviews/isometric-room-preview.png` 来自正式模型和绘制模块的示例摆放，并非真机截图；不向用户数据库添加示例家具。
- 已验证两条地面轴斜率为 ±1/2、垂直高度投影，以及互换几何绘制顺序后的遮挡一致性。渲染测试涵盖普通与镜像家具、空房间和完整摆放示例。
- `PixelPalette.swift` 集中管理更鲜明的游戏像素配色；几何模块新增软体倒角、圆台和轮廓挤出。沙发坐垫、背包肩带、贝壳灯、圆形垃圾桶与原木端面拥有独立剪影；大冰箱使用双门宽机身，电视柜包含屏幕，镜柜包含可收纳柜体。
- 自动造型按名称与图标匹配，用户明确选择的造型优先；“镜柜、小推车、墙壁”均有正式模型，不再映射成普通镜子、默认纸箱或窗户。新建容器选择造型时仅在名称空白/仍为上一个默认名称时同步默认名称，保留用户自定义名称。
- 新的 `DesignPreviews/furniture-catalog-update.png` 与 `furniture-scene-update.png` 是正式代码渲染结果。已验证造型映射、放置边界、图层前后移动、镜像/缩放/造型持久化，以及收起家具后物品不变；模型存储字段没有修改。
- 本轮加号拍摄流程、无卡片边框贴纸和固定装修面板已通过 iOS 17 编译，并由 Xcode 在 OGS17 更新安装、启动。相机取景、拍照回填和面板实际触摸手感尚未由 Agent 进行真机交互验证。

## 下一次真机查看

1. 首页点击加号直接进入拍照，使用照片后显示信息表单，查看权限、取景、对焦、快门和贴纸处理。
2. 取消拍照后原照片应保持原样；相册从录入页进入；连续换图应只保留最后一张。
3. 手动填名字后保存，返回列表应显示名称，不显示“识别中”。
4. 编辑物品后取消，原信息不变；编辑后保存，图片、容器和数量一致。
5. 查看物品详情的返回按钮，以及小房间展开/收起、拖拽入容器和装修固定面板；检查造型抽屉、镜像、前移/后移和大小调整。
